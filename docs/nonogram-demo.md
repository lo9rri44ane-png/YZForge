# 数织 Demo

本文仅依据当前源码说明实现，不引用外部资料。当前是可玩、可编辑的原型，不是已完成美术和难度标定的正式关卡产品。

## 启动入口

在 PinK 打开项目，打开 [启动场景](../assets/game/boot/Bootstrap.scene)并预览；Web 目标默认使用 `web-mobile`。启动接入点 [start-game.ts](../assets/game/app/start-game.ts) 当前直接挂载 `NonogramDemo`，不进入原展示首页：优先查找 `GameRoot/Canvas`，否则使用场景中的原生 `Canvas`，两者都不存在则报错。新建宿主节点随本次启动作用域清理。

[界面实现](../assets/game/app/nonogram/NonogramDemo.ts)运行时创建棋盘和控件，无预制体依赖，以 720×1280 竖屏布局等比适配父级。预览前的配置生成与检查要求见 [PinK 工作流](pink-workflow.md)；本文未新增预览、构建或真机验收记录。

## 玩法与操作

- 左侧数字对应行，上方数字对应列，按顺序表示连续填色段长度；不同段之间至少空一格。空行/列显示 `0`，每五格加粗网格。
- 选择“■ 填涂”或“× 标空”，点击或拖动落笔；起点已经是当前目标状态时，本笔改为擦除。拖动在采样点之间补格，同一笔不重复处理同一格；出界立即结束，需抬手后重新落笔。
- 一笔作为一次撤销记录；支持撤销、重做，新操作清空重做历史。仅处理当前活动触点，不支持多指同时绘制。
- 行列连续段与提示完全一致时，剩余未操作格显示自动叉。自动叉仅由当前手动作答派生，不写入手动格或撤销记录；取消填色后即时撤去失去依据的自动叉，手动叉保留，另一个已完成行列仍可维持自动叉。自动叉格可直接填色。提示、撤销、重做均走同一派生显示，重开、导入和编辑切换不保留自动叉状态。
- 提示数字使用独立文字节点：只将所有顺序匹配都确认的数字置灰，例如提示 `1 2` 仅填成连续两格时只灰 `2`；重复数字无法确定归属时不灰，顺序矛盾也不灰，整行完整匹配则全部灰。取消填色即时恢复亮色；编辑答案时不置灰。
- 填色位置与保存的答案完全一致即通关，空格不必全部打叉；通关停止计时和继续落笔，可撤销或开新关。多解自制题仍按保存的答案判胜，不接受任意等价解。
- 每次从未通关变为通关时显示一次“恭喜通关”上移淡出浮字；重开、撤销及组件销毁清理浮字和动画，不逐帧重复播放。
- “新关”按当前规模重新生成；“重开”清空作答、历史、计时和辅助标记，不更换答案。编辑时重开不清空答案。
- “提示”不限次数，直接按答案修正首个填色状态不符的格子，可撤销，并标记使用过答案辅助；它不是逻辑推导提示。“★ 无限练习”仅显示说明，没有额外关卡系统。

## 编辑、导入与导出

1. 点击“编辑答案”，直接在当前答案上绘制或擦除，行列数字实时更新；编辑支持撤销、重做，不计时。编辑时尺寸按钮创建对应大小的全空答案，切换前应自行保存。
2. “验证”分析当前答案的提示是否唯一、是否由当前传播器无分支解出，并显示启发式分类、传播轮数和搜索分支数；它不自动修改或拒绝题目。
3. “试玩 / 返回”保存答案草稿并从空盘试玩，再点击恢复答案编辑；试玩进度不带回编辑。退出编辑也会保存答案并开始该题作答；试玩中另开新关会丢弃内存中的返回入口。
4. “导出”将 `{ version: 1, size, solution }` 写入界面文本框，手动选择复制；导出的是答案，不是作答进度。`solution` 是按行从左到右、从上到下排列的 `0/1` 数组。
5. 将 JSON 粘贴进文本框后点击“导入”。仅允许尺寸 5、10、15，数组长度必须为尺寸平方且每项为数字 `0` 或 `1`；成功后进入编辑模式，建议先验证再试玩。当前不校验 `version`，也不在导入时强制唯一性。

退出编辑、进入试玩、导入和导出时会尝试把答案保存到本地键 `nonogram.draft.v1`；并非每笔自动保存。重启发现有效草稿时只填入文本框，仍先生成新关，需点击导入恢复。存储损坏或不可用不阻断游戏；没有作答进度存档、文件下载或种子导入界面。

## 种子生成与规模档位

[逻辑实现](../assets/game/app/nonogram/NonogramLogic.ts)的 `generatePuzzle(difficulty, seed)` 接受有限数字种子，以 `seed >>> 0` 初始化伪随机状态；相同实现、档位和种子可复现结果，不同输入种子可能映射到同一 32 位初始状态。界面新关使用 `Date.now()`，未展示或保存种子。

| 请求档位 | 界面名称 | 尺寸  | 随机填色概率 |
| -------- | -------- | ----- | ------------ |
| `easy`   | 入门     | 5×5   | 0.70         |
| `normal` | 进阶     | 10×10 | 0.60         |
| `hard`   | 挑战     | 15×15 | 0.55         |

最多检查 24 个随机答案：只保留唯一解，遇到分析分类与请求档位相同的题就立即返回；否则返回最先发现的唯一解。若全未找到，使用种子打乱长度 1 到尺寸的各行，每行从左边缘连续填色，形成嵌套行答案，再验证唯一性；这是兜底，不保证图案品质或目标难度。

返回值包含 `size`、`solution`、原始 `seed`、请求 `difficulty` 和 `analysis`。请求档位控制规模与密度，**不保证实际分析难度**，也不保证无分支逻辑可解；15×15 仍可能被判为 `easy`。当前 JSON 导出不包含种子、分析结果或生成器版本。

## 唯一性求解与当前难度含义

`getClues` 从方形二值答案提取提示，空行用空数组。`solvePuzzle` 本身也支持矩形提示：

1. 枚举每行、每列满足提示和段间空格要求的全部候选排列。
2. 用已知格过滤候选，将同一位置所有剩余候选一致的值写回棋盘，反复扫描至稳定；候选为空则该路径矛盾。
3. 未完成时，选剩余候选数最少且大于一的行或列，逐个尝试完整排列并递归；找到两个解即停止。因此解数组长度 0、1、2 分别表示无解、唯一解、至少两个解，不是完整解数统计。

`logicSolved` 仅表示根状态不经过分支、靠上述候选传播就完成，不是“搜索最终找到唯一解”，也不是已按人类规则输出推理步骤。`rounds` 累计所有访问状态的完整传播扫描次数，包含最终无变化的扫描；`branches` 累计尝试的候选排列决策数，不是搜索深度或人类猜测次数。

`analyzePuzzle` 的实际分类顺序如下：

- 非唯一解：`ambiguous`。
- 唯一解且 `branches > 0`：`hard`，界面显示“需分支搜索”。
- 唯一解、无分支且 `rounds > 3`：`normal`，界面显示“中等”。
- 其余唯一解：`easy`，界面显示“简单”。

这是依赖当前算法和扫描顺序的启发式，不是人类难度评分。由合法答案生成的提示至少有该答案，因此此处非唯一通常是多解；底层求解器仍能识别无解提示。没有按尺寸直接划定实际难度，也没有具名人类规则评分器。

## 推荐正式关卡流水线（待实现）

推荐顺序：**图案 → 提示 → 唯一解 → 无猜测逻辑验证 → 人类规则评分 → 种子与版本存档 → 批量关卡审核**。

1. **图案**：设计可辨识的二值图案，检查轮廓、留白与移动端可读性；随机答案只作为候选来源。
2. **提示**：从答案生成行列提示，校验尺寸、数据和答案一致性。
3. **唯一解**：以最多两解的求解结果筛除无解、多解题，不能只检查提示吻合。
4. **无猜测逻辑验证**：在明确允许的规则集合下，从空盘记录每一步依据；要求无需假设或回溯即可完成。当前 `logicSolved` 可作为候选传播筛选证据，但不能替代具名人类规则验证。
5. **人类规则评分**：记录最高规则等级、关键步骤、推理链长度和停滞点，再结合盲测调节门槛；不要直接用尺寸或搜索分支数作为玩家难度。
6. **种子与版本存档**：保存关卡 ID、答案、提示、规范化种子、请求档位、生成器/求解器/评分规则版本及验证报告。手绘题注明来源；种子不能替代实际答案归档。
7. **批量审核**：复跑唯一性和无猜测验证，检查重复题、难度分布、兜底题占比、图案品质与提示排版，形成可追溯的发布清单。

### 推荐人类规则门槛

以下均为**设计建议，尚未实现或标定**，不是当前 `easy/normal/hard` 的判定条件：

| 建议难度 | 建议允许的规则门槛                                                                                             |
| -------- | -------------------------------------------------------------------------------------------------------------- |
| 简单     | 满行/空行、基础重叠、已完成段封边及直接剩余空间判断；尽量局部可见、推理链短。                                  |
| 中等     | 在简单规则上加入边界约束、段位置排除及多轮行列交叉传播，仍不使用假设。                                         |
| 困难     | 允许更复杂的候选段归属、组合排除与较长交叉推理链；每步仍需可解释且无猜测，不把必须分支搜索作为正式困难题门槛。 |

美术风格、图案库、完成反馈与资源制作待补；玩家盲测、难度校准、触控体验及不同设备上的可读性验收也待补。当前原型与逻辑测试不能替代这些工作。
